## 1. Steamworks SDK 票据签名演化(已核实并落入代码)

| SDK 版本 | ISteamUser 接口 | GetAuthSessionTicket C++ 签名 |
|---|---|---|
| ≤ 1.55 | SteamUser021 | `(pTicket, cbMaxTicket, pcbTicket)` — 3 参,无 identity |
| ≥ 1.56 | SteamUser022/023 | `(pTicket, cbMaxTicket, pcbTicket, const SteamNetworkingIdentity*)` — 4 参 |

- 证据:Proton 自带历代 SDK 头文件;`steamworks_sdk_156/isteamuser.h` 起出现 identity 参并同时升 v022。
- 当前 dst 目录 DLL 导出 `SteamAPI_SteamUser_v021`(旧签名),4 参调用实测可用(2026-10-26 登录成功)。
- **万能修法(已实施)**:ctypes `argtypes` 固定 5 参、identity 永远显式传 `None`——
  旧签名 DLL 多压一个栈参数无副作用;新签名 `NULL identity` = 通用票据。
- **identity 必须为 NULL**:官方头文件(SDK 165 isteamuser.h)原话注释:绑定 identity 的票据
  "not to be used for ISteamUserAuth\AuthenticateUserTicket — it will fail",
  而 Klei 服务端正是走 `AuthenticateUserTicket` 验票。
- 偶发 `handle=0` 的另一独立原因(2026-10-26 实测):Steam user 上下文未就绪,
  重试即可恢复(脚本已带 5×1.5s 重试)。

## 2. SteamKit2:纯 CM 协议出票,连 Steam 客户端都不用开(路线图备选)

- SteamKit2 `SteamAuthTicket`(NuGet 3.5.0+,活跃维护)能纯 CM 网络协议生成会话票据:
  CM 登录(账密+Steam Guard)→ ClientGameConnectTokens → GetAppOwnershipTicket(322330)
  → HMAC 构造 → ClientAuthList/CRC 确认 → CombineTickets,产出与游戏客户端同格式票据。
  2025-08 Steam 的 ack 改动(issue #1567)已适配。
- 项目意义:~100 行 C# 出票工具(hex 到 stdout)→ 现有 `klei_steam_login.py` 直接喂;
  部署从"必须 Steam 客户端"降为"账号凭据+2FA 一次"。多账号时代与"token 链式续期"
  二选一或组合(SteamKit2 负责"每账号首票",链式续期负责日常)。
- 实验:先 `GetAuthSessionTicket`(TicketType.AuthSession=2,与游戏同款),
  不行再 `GetAuthTicketForWebApi`(type 5)。
- 风险:CM 登录需托管凭据与 sentry 文件,属第三方库登录,风控自担。**暂不实施,记录备选。**

## 4. 诊断树(留档:若未来换新 DLL 后拿不到票)

1. dump DLL 导出表,确认 `SteamAPI_SteamUser_vNNN` 版本;
2. 按 5 参 identity=None 修签名重跑(已内置);
3. 仍为 0 → 查 Steam 客户端在线(离线模式 InitEx 成功但出票需连后端)、
   pump `SteamAPI_RunCallbacks` 后重试、确认账号拥有 DST(appid 322330)。
